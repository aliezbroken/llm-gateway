# 需求分析（Requirements Analysis）

> 一个"精简版 New API" 面板：前置网关 + 令牌/账户管理 + 配额计费 + 用量统计。
> 项目位置：`D:\leaf-unet_predict\gateway`（独立子项目）

## 1. 项目目标

在 vLLM（OpenAI 兼容上游，单通道，地址通过环境变量 `UPSTREAM_URL` 或后台系统设置配置）前搭建一个统一网关面板，对外提供 OpenAI 兼容 API（`sk-` 令牌鉴权），对内提供 Web 后台（JWT 登录），实现：

- 管理员：用户管理、配额分发、令牌审计、全量日志统计、上游配置与健康检查
- 普通用户：自助创建令牌、查看令牌额度、查看自己的用量与请求日志

## 2. 角色与权限

| 角色 | 说明 | 能力 |
| --- | --- | --- |
| `admin` 管理员 | 系统唯一配置方 | 用户增删改查/启停、手动分发配额、查看全量日志与统计、配置上游地址与模型倍率、健康检查、令牌全量管理 |
| `user` 普通用户 | 消费者 | 登录、查看自己的配额与流水、创建/停用/删除自己的令牌、查看自己的用量统计与请求日志 |

约束：普通用户只能操作**自己的**数据；所有写操作（配额变动、用户变更）写入审计流水，仅管理员可见。

## 3. 功能模块与优先级

### P0（必须）
- **1. 认证**
  - 面板登录：用户名 + 密码 → JWT
  - API 鉴权：`Authorization: Bearer sk-xxx`（令牌）→ 网关放行
- **2. 用户管理**（仅 admin）
  - 新增/编辑/删除用户、启用/停用
  - 手动分发配额（增加/扣减/清零），记录操作人与原因
  - 重置用户密码
- **3. 令牌管理**
  - 用户生成 `sk-` 令牌（带名称、额度上限、IP 白名单、并发上限）
  - 密钥明文仅创建时展示一次，库中存哈希
  - 启停/删除；额度上限自动失效；IP 白名单校验；并发控制
- **4. 网关代理**（P0 核心）
  - 转发 OpenAI 兼容请求到单上游 vLLM（支持流式 SSE 与普通 JSON）
  - 令牌校验 → IP 白名单 → 并发上限 → 配额校验 → 转发 → 解析 `usage` → 扣费 → 落日志
  - 配额不足/令牌失效返回 402/401 语义错误
- **5. 请求日志**
  - 记录：时间、用户、令牌、来源 IP、模型、端点、prompt/completion/total tokens、配额消耗、延迟(ms)、状态
  - 查询列表 + 多维过滤（时间范围、用户、令牌、模型、状态）
- **6. 统计仪表盘**
  - 请求量/消耗 token/配额消耗/平均延迟 概览卡片
  - 请求量与 token 时间趋势图、响应时间 P50/P95/P99
  - 按用户/令牌/模型的用量分布

### P1（重要但可后置）
- 配额流水（ledger）页面
- 令牌的最近用量、日志联动

### P2（明确不做，精简）
- 多渠道路由/权重/故障切换（仅单上游）
- 兑换码/充值/支付
- 令牌过期时间、模型绑定（用户已确认不需要）
- 用量排行导出 Excel/CSV
- 多机部署（并发控制依赖单进程内存，文档注明）

## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 性能 | 网关转发为纯流式透传，字节级开销；单进程 asyncio 可支撑数百并发 |
| 可用性 | 计费与日志尽量原子；单进程故障由 systemd 自动拉起（Restart=always），可用性依赖上游 vLLM |
| 安全 | 密码 bcrypt 哈希；令牌密钥 SHA-256 哈希存储；JWT 无状态；管理接口强制 admin |
| 数据 | SQLite 单文件，启动自动建表；日志表按时间可清理 |
| 可维护 | 模块清单见 ARCHITECTURE.md，模块间仅通过 service 层交互 |
| 部署 | 单机 `systemd + uvicorn` 单进程：同一实例提供 `/v1/*`、`/api/*` 并直接托管前端静态页（无需 nginx）；`npm run dev` 开发代理 |
